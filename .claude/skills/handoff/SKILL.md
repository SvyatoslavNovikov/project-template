# handoff

Новая сессия с handoff-файлом стоит 30–60K токенов на входе. Продолжение сессии с контекстом 300K+ стоит столько же на каждый шаг, а форк копирует весь контекст. Поэтому на границе фаз — handoff.

## Что записать

Файл `docs/handoff/YYYY-MM-DD-<тема>.md` (тема латиницей через дефисы, например `prj-12-decomposition`). Если файл по теме уже есть — обновить его, а не создавать второй. Не длиннее 60 строк, содержимое файлов не пересказывать: они на диске.

```markdown
# Handoff: <тема> (<дата>)

## Цель
Одна-две строки: что делаем и зачем.

## Решения
- <решение> — кто принял (пользователь / встреча <дата> / комментарий в макете), источник.

## Файлы
- `<путь>` — состояние: черновик / проверен ревьюером / реализован / выгружен (куда).

## Вопросы
- Открытые и закрытые вопросы (кем закрыты), со ссылками на файлы.

## Внешние ссылки
ID требований и тестов, ключи задач во внешних трекерах, ссылки на макеты и страницы.

## Дальше
1. Следующий конкретный шаг (с командой, если она есть).
2. …

## Не делать
Что уже отвергнуто и почему, чтобы новая сессия не предложила это снова.
```

## Правила

- Только факты из сессии и файлов: чего не знаешь — `TBD`. Решения, которые пользователь не принимал, решениями не называть.
- Токены, пароли, содержимое env не записывать.
- В конце сказать пользователю, как продолжить: открыть новую сессию с сообщением «Продолжаем по `docs/handoff/<файл>`».
- Коммитить только по просьбе пользователя. Когда работа по теме закончена, файл удалить (тоже по его слову): история останется в git.
