# meeting-notes

Конспект — источник для решений, а не замена требований. Решение считается принятым, когда оно записано в эпике или стори, которые оно меняет.

## Файл

`docs/meetings/YYYY-MM-DD-<slug>.md` (slug латиницей через дефисы, обычно ID эпика и тема, например `prj-12-onboarding`). Каталог создать, если его нет.

```markdown
# <Тема> (<DD.MM.YYYY>)

Эпик или стори: `PRJ-<n>` …
Запись: <ссылка> (~N мин), если есть.

## Участники
- Имя (роль)

## Итог
2–4 предложения: что решили, что осталось открытым, кто что делает дальше.

## Решения
- <решение> — кто принял; затрагивает `PRJ-<n>`.

## Открытые вопросы
- <вопрос> — к кому, к какому сроку; затрагивает `PRJ-<n>`.

## Дальше
- <действие> — кто.
```

## Решения → требования

1. Для каждого решения найти артефакты, которые оно меняет: эпик (скоуп, вне скоупа, критерии успеха), стори (критерии приёмки), SR или NFR (Statement, метрика).
2. Показать пользователю, что и где предлагается изменить, и вносить после его подтверждения. Новые стори и SR — через агента `req-writer` или по шаблонам, с ID из реестра.
3. В изменённом артефакте — ссылка на конспект рядом с изменённым местом (`см. docs/meetings/<файл>`), `updated` — дата правки. Статус артефакта, который уже `approved`, не менять самому: сказать пользователю, что требование изменилось и его нужно перепроверить.
4. Решение противоречит уже записанному требованию — не сглаживать: показать оба варианта и источник каждого, выбор за пользователем. Неразрешённое противоречие между двумя требованиями — связь `conflicts-with`.
5. Новый термин или роль — сначала строка в `GLOSSARY.md`.

## Правила

- Конспект по факту сказанного, а не по плану встречи. Решением называть только то, что участники явно приняли; предложение без согласия — в «Открытые вопросы».
- Неразборчивое или предположительное в расшифровке (кто говорил, точная цифра) — помечать прямо в тексте, не выдавать за факт.
- Длинную расшифровку читать агентом (`general-purpose` с `model: sonnet`), в основной поток — черновик конспекта и список решений со ссылками на места в расшифровке.
- Персональные данные, не нужные для требований (телефоны, личные обстоятельства), в конспект не переносить.
- Коммитить только по команде пользователя.
