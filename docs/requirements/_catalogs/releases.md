# Releases

Справочник версий продукта — как Versions / Fix Version в Jira.

Это **не тикеты**: строки не получают `PRJ-<n>` и не живут в дереве эпик → стори → SR.

- Добавить релиз: новая строка в таблицу.
- Указать релиз в тикете: ключ в поле `releases`.
- Указать релиз в прогоне: ключ в поле `release`.

Скоуп версии — все тикеты, у которых в `releases` есть этот `key`. Обратный список на справочнике не ведём.

| key | name | status | start | released | notes |
|---|---|---|---|---|---|

`status`: `unreleased` | `released` | `archived`

Правила:

- `key` уникален и стабилен (его пишут в тикетах). Менять `key` нельзя — только `name`.
- Для новых тикетов не выбираем `archived`.
- Пустое `releases` / `release` допустимо: тикет ещё не запланирован в версию, прогон не сертифицирует поставку.
- `build` у прогона — сборка продукта, не замена `key`.
- `revision` у прогона — commit репозитория (какие шаги кейсов действовали), не замена `key`.
