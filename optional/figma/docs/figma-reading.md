# Чтение макетов Figma агентом

Рецепт для агента `figma-reader`. Собран по сессиям проекта ELKA (10.2026): приёмов, которых там не проверяли, здесь нет, неподтверждённое помечено TBD. Найдёте новый рабочий приём или сбой — допишите сюда.

## 1. Какой браузер
- Встроенный браузер (`mcp__Claude_Browser__*`) без входа в Figma показывает логин. Рабочие пути: пользователь входит в Figma вручную в панели браузера, потом агент работает; или Claude in Chrome (`mcp__claude-in-chrome__*`), где сессия пользователя уже есть.
- В субагенте инструменты Claude in Chrome доступны, но своей группы вкладок нет: `tabs_context_mcp` без параметров отвечает «No tab group exists». Первым вызовом — `tabs_context_mcp` с `createIfEmpty: true`.
- Логины и пароли агент не вводит: видит экран входа — останавливается и просит пользователя войти.

## 2. Открыть макет и перейти к фрейму по node-id
- `navigate` на `https://www.figma.com/design/<fileKey>/<name>?node-id=<a>-<b>`. node-id через дефис, имя файла можно сократить до `x`.
- Несколько фреймов — одним `browser_batch`: `navigate; wait; screenshot; navigate; wait; screenshot…`.
- Тяжёлый файл грузится 20–30 с (`wait 10` два-три раза). Первый `screenshot` часто падает с «Script injection timed out after 5000ms»: это не ошибка URL, ещё `wait 10` и повтор.
- После загрузки `key shift+2` (zoom to selection) приближает выбранный по node-id фрейм, `shift+1` — «показать всё».
- После `navigate` на другой node-id в том же файле первый кадр бывает чёрным со скелетоном: ещё `wait 20` и повторный `shift+2`.
- node-id может указывать не на экран, а на секцию или плашку-заголовок с сеткой кадров под ней. Тогда кадры читать по очереди, у каждого фиксируя имя; соответствие другим node-id без проверки — TBD.
- Узнать node-id выбранного узла можно по `location.href` (`javascript_tool`), но из субагента он возвращает «[BLOCKED: Cookie/query string data]»: в агенте node-id брать только из ссылок.
- Масштаб вручную: клик по полю зума, `triple_click`, `type "75%"`, `Return`.

## 3. Тексты без скриншотов
- `get_page_text` на вкладке Figma — самый дешёвый первый шаг: названия страниц файла, текстовые слои и заметки дизайнера на странице, иногда список комментариев «#номер · страница / автор / давность / текст».
- Тексты внутри кадров макета через `get_page_text` или DOM не читаются (TBD): их читают по `zoom`.
- Комментарии на холсте: `find` и `read_page` видят только регион «Comments on canvas» без текстов. Если `get_page_text` комментариев не вернул, читать панель Comments по скриншоту, развернув её; номер и автора без чёткого скриншота помечать TBD. У каждого комментария есть номер (#2300) — его указывать в источнике факта.
- Сниппет по `aria-label` комментариев (после открытия панели) ненадёжен: бывает пусто или только «Comment (N unread)».

```js
[...document.querySelectorAll('[aria-label^="Select comment"], button')].map(b=>b.getAttribute('aria-label')||'').filter(t=>t.startsWith('Select comment')).slice(0,12).join('\n')
```

- Имена страниц и фреймов в левой панели с координатами для клика (`k` переводит CSS-пиксели в рамку скриншота; ширину рамки брать из ответа `screenshot`, список имён — свой):

```js
const k=<ширина рамки>/window.innerWidth; Array.from(document.querySelectorAll('span,div')).filter(e=>e.children.length===0 && e.innerText && e.getBoundingClientRect().width>0 && e.getBoundingClientRect().left<400 && ['<имя фрейма>'].includes(e.innerText.trim())).map(e=>{const r=e.getBoundingClientRect();return {t:e.innerText.trim(), fx:Math.round((r.left+r.width/2)*k), fy:Math.round((r.top+r.height/2)*k)}})
```

Затем `left_click [fx, fy]` и `shift+2`. Без фильтра по именам сниппет возвращает список всех страниц файла.

## 4. Когда нужен скриншот
- Нужен для текстов и состояний самого макета (кнопки, заголовки, заглушки). Вместо полного скриншота — `zoom` по областям `region=[x0,y0,x1,y1]`, несколько областей одним `browser_batch`.
- `zoom` не увеличивает холст, а только вырезает область: мелкий кадр так не прочитать. Сначала приблизить холст (`shift+2` на нужный кадр или 100%), потом `zoom`.
- Для навигации и проверки «загрузилось ли» — `screenshot` со `scale` 0.5–0.6, полный размер только перед `zoom` по тексту.
- Ориентир объёма: 12–34 скриншота на одну историю.

## 5. Известные сбои
- Клики по холсту промахиваются, если `devicePixelRatio` не 1: координаты из `getBoundingClientRect` умножать на `k = <ширина рамки скриншота>/innerWidth`, иначе «outside the coordinate frame».
- Рабочая область вкладки агента бывает меньше рамки скриншота (остальное белое): координаты кликов и `zoom` брать внутри неё.
- Селекторы панели слоёв (`[data-testid*=layer]`, `[class*=object_row]`) и `find`/`read_page` панель слоёв не видят: обход — сниппет по `span,div` из раздела 3.
- Селектор вкладки `Comments` по тексту не находит её: открывать панель кликом по иконке в тулбаре по скриншоту и проверять скриншотом, что открылась именно она (бывает переключение на Properties).
- `ctrl+f` по файлу для перехода к фрейму надёжно не работал (TBD).

## 6. Минимальный порядок
1. node-id — из ссылок в требованиях, задаче или брифе (`grep figma.com` по `docs/`).
2. `navigate` на первый node-id, ожидание 20–30 с, `shift+2`.
3. `get_page_text`: страницы, текстовые слои, комментарии.
4. `zoom` по областям с текстом, один-два `browser_batch` на кадр.
5. Результат с node-id и номерами комментариев — в файл (`tmp/agents/figma/<тема>/figma.md` или путь из брифа). Тяжёлое чтение (больше 10 скриншотов) — только агентом, не в основном потоке.
