# testit

CLI: `python scripts/testit_cli.py`, запуск из корня репозитория. Настройки — `scripts/testit.config.json` (проект, секция, конфигурация), токен — env `TMS_PRIVATE_TOKEN` (не печатать, не вставлять в команды).

## Кейсы

1. Кейсы проверены: `python .claude/hooks/docs_lint.py docs/tests` без ошибок.
2. Dry-run и показать пользователю, что будет создано и обновлено:

```bash
python scripts/testit_cli.py push-cases docs/tests/cases
```

3. Только после его «да» — та же команда с `--apply`. Хук `external_write_guard` спросит подтверждение ещё раз: это не замена команде пользователя.

Что уходит: имя «<ID> <title>», «Цель» — описание, «Предусловия» — шаги предусловий, «Шаги» — шаги, «Ожидаемый результат» — на последнем шаге, метки — ID кейса и `tags`. Статус кейса → состояние work item (`draft` → NotReady, `review` → NeedsWork, `approved`/`automated` → Ready), `priority` → High/Medium/Low. Кейс без шагов и `obsolete` пропускаются. Кейс с `external.testit` обновляет свой work item, а не создаёт второй.

## Результаты прогона

```bash
python scripts/testit_cli.py push-results docs/tests/runs/PRJ-T-<n>-tr-<slug>
```

- Все кейсы прогона должны быть уже выгружены (`external.testit`), иначе CLI остановится и перечислит их.
- Результаты идут через автотесты: `externalId` автотеста = ID кейса (`PRJ-T-<n>`), он стабилен и связан с work item кейса. Ручной результат прямым API не записать, поэтому и ручной прогон попадает в Test IT как результаты автотестов.
- `not-run` не отправляется. Комментарий строки — `message` результата. ID тест-рана записывается в `external.testit` прогона.
- Повторный `push-results` по тому же прогону создаст второй тест-ран: перед ним спросить пользователя.

## Правила

- Источник правды — репозиторий: кейс правят в `docs/tests`, потом `push-cases`. Правки шагов прямо в Test IT следующий push перезапишет — предупредить пользователя.
- ID проекта, секции и конфигурации не угадывать: из конфига или у пользователя.
- `externalId` автотеста не менять: в Test IT он связывает историю результатов с кейсом.
- Ошибка 401/403 — проверить, что `TMS_PRIVATE_TOKEN` задан (без вывода значения); 400 — показать текст ответа, поле не угадывать.
